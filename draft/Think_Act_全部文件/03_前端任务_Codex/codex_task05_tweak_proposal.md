# Codex 任务书 · 前端 Task 05 —— 点选微调(looks good 之前编辑提案)

> 用法:贴给 Codex。
> 前置都已就绪:提案屏 + looks good 存库(Task 03/04)。本任务全部在客户端,改的是"还没存的提案",不动后端。

## 背景

现在 AI 出的提案是"全收或重来"——用户只能点 looks good 整个接受,或重新生成。但 AI 不总是完美,用户该能在确认前**轻量地改**:删一项、改个时间、切 ★、加一项。这是早上「确认」这个安全网的最后一块(我们的理念:AI 猜八成,用户秒改)。

## 任务目标

在提案屏上,对每个任务卡支持以下编辑(都作用在**内存里的提案**,点 looks good 时保存的是改过的版本):

1. **删除**:从提案里移除某项(X 按钮或左滑删除)
2. **改时间**:点时间药丸 → 时间选择器 → 更新该任务的 planned_start;列表按时间重新排序
3. **切换 ★**:点星标区域 → important 在 true/false 间切换(**不限制数量**——用户想标几个标几个,这是他自己的计划)
4. **加一项**:列表底部一个「+ 加一项」→ 输入标题 + 时间 → 加进提案

编辑都是**轻量内联**,不要搞复杂的编辑模式开关——点时间就改时间、点 X 就删、点星就切。

## 用户手动加的任务,字段怎么填

- title:用户输入
- planned_start:用户选的时间(今天 + 选的 HH:mm,合成 ISO)
- planned_duration:默认 30 分钟
- important:默认 false
- source:`user_text`(用户自己加的)
- time_of_day:按时间推断(<12 morning,12-14 midday,14-18 afternoon,>18 evening)
- task_type:留空(null,schema 允许)

## 保存时(looks good)

- 沿用 Task 04 已有的存库逻辑(先软删今天旧 planned,再批量插入)。
- 插入的是**用户编辑后的提案**:删掉的不存、改过时间的用新时间、切过的 ★ 用新值、加的也一起存。

## 设计

- 全部沿用已锁定的陶土设计系统,别引入新样式。
- 删除/编辑的操作要轻、要明显但不抢戏(比如时间药丸点上去有反馈、X 按钮淡一点)。

## 范围外(后面单独做)

- 日常 / routine(下一个功能)
- 硬约束确认弹窗
- 语音输入
- 拖拽排序(改时间已经能调顺序,不用拖拽)

## 验收标准

1. 提案里删一项 → 它消失,列表正常。
2. 点某项时间 → 改成别的时间 → 卡片更新,列表按新时间排序。
3. 点 ★ → 能开能关;连标 3 个也允许(不拦)。
4. 「+ 加一项」加一个 AI 没给的任务(标题 + 时间)→ 出现在列表对应时间位置。
5. 做完上面这些编辑,点 looks good → 去 tasks 表看:删的没存、改时间的是新时间、加的在(source=user_text)、★ 状态对。
6. 全程陶土风格不走样。

## 完成后输出

1. 代码 + 一段录屏:删一项、改个时间、加一项、点 looks good。
2. 一张 tasks 表截图,证明存的是编辑后的版本。
3. 一句话:有没有哪个编辑交互你拿不准、想让设计师定的(比如删除用 X 还是左滑)。
