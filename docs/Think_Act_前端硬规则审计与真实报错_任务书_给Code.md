# Think & Act ｜前端硬规则审计 + 真实报错(测试期)·任务书(给 Code)

## 背景 / 根因(老板测试发现)
很多调整做不了:**前端把业务规则硬编码写死,在请求到后端/LLM 之前就把用户/LLM 想做的灵活操作挡掉了**。已修 2 个,疑似还有不少。

## 原则(贯穿)
**前端是"哑"的捕获 + 渲染层,不做业务判断。**
- "这个调整能不能做、合不合理" → **后端 / LLM 决定**,不是前端。
- 前端只负责:把用户/LLM 的意图**原样送过去** + 把后端返回的结果**原样渲染**。
- 前端**唯一**可以拦的是"技术上不可能"(数据格式坏了、会崩),**不是**"业务上我觉得不该"。
- Think & Act 具体:调整 = FE 捕获自然语言 → `/plan-revise`(或 `/review-parse-voice`,**LLM 解释意图**)→ 渲染前后对比 → 确认后 `apply`。**FE 不自己解析意图、不预判合理性、不过滤 LLM 提议的操作。**

---

## 任务 A:打开"真实报错 + 拦截可见"调试模式 **(先做,这是探照灯)**
加一个测试期开关(如 `DEBUG_VERBOSE`)。开启时:

1. **失败不走友好兜底,摊开真实底层错误**,标明卡在哪一层:
   - 层级:**FE 规则 / 后端 / LLM / 网络**
   - 后端:endpoint + HTTP 状态 + 错误码 + **原始 message**(如 `review-apply → 409 REVIEW_STALE`)
   - LLM:用户原话 + LLM 返回的**原始结构** + FE 如何处理的
   - 网络:真实网络错误
2. **静默拦截也要发声**(关键 —— 这是抓出剩余硬规则的办法):
   任何 FE 对用户/LLM 操作的 **reject / clamp / filter / drop**,**即使不报错**,也要在调试浮层/日志里打出来。例:
   - 「FE 拦截:规则 X 丢掉了 move 操作(原始意图:把深度活儿挪到 09:00)」
   - 「FE 夹断:时长 200min → 180min」
   - 「FE 忽略:LLM 返回的 2 个操作里第 2 个被过滤」
3. 生产 build 保留友好文案;**测试 build 走 raw**。

> 目的:每次"做不了",你一眼看出卡在 FE 规则 / 后端 / LLM / 网络的哪一层、原始原因是什么。

## 任务 B:前端硬规则审计 → 改透传
1. **盘点**:列出 FE 中所有"在发送前对用户/LLM 请求做 验证/拒绝/夹取/转换/丢弃"的点,以及"对后端/LLM 返回的操作做 过滤/忽略"的点。每条给 **file:line + 规则 + 挡住了什么**。
2. **逐条分类**:
   - 真·技术约束(防崩溃 / 数据格式)→ **保留**
   - 业务规则 → **删掉**,或**移到后端**(后端拦 + 返回明确 reason,不在 FE 静默挡)
3. **默认透传**:拿不准的一律**放行到 `/plan-revise` / `/review-apply`**,让 LLM/后端处理与拒绝。**FE 不替后端拒。**

### 硬规则常见藏身处(照着挖)
- **时间**:不准排到过去 / 跨午夜 / 时长必须在某区间 / 不准重叠 / 必须对齐整点或 15 分钟
- **状态**:完成的任务不准改 / 跳过的不准恢复 / 重排超过 N 次不准再排
- **数量·结构**:一天最多 N 件 / 必须有标题 / ★ 最多 N 个
- **来源**:微信来的 / AI 建议项 不准编辑或直接改
- **解析**:FE 自己判断用户意图(该交 LLM)、或把 LLM 返回的某些操作过滤掉

## 验收
1. ✅ 调试模式下,每次"做不了"都能一眼看出**卡在哪层 + 原始原因**;静默拦截也会冒出来。
2. ✅ 审计清单产出(file:line + 规则 + 挡住什么);业务规则已删 / 移后端,FE **默认透传**。
3. ✅ 之前做不了的几个真实灵活操作(老板给例子)现在能**走通到 `/plan-revise` 并由 LLM 决定**。
4. ✅ 真需要的拦截 = **后端返回明确 reason**,FE 不再静默挡。
5. ✅ Android / iOS 一致;双端验证,done 老板按效果拍。
