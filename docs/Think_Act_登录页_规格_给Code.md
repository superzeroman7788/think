# Think & Act ｜登录页规格(给 Code)

> 视觉对回 `登录页_设计_v1.html`。**发朋友版:手机号 + 验证码,但本版先 mock 登录;微信登录占位。**

## 屏(照 demo)
- 品牌区:`think & act` + 「你的一日搭子」+ tagline + 柔光。
- 手机号(+86)输入 + 验证码输入 + **获取验证码**(60s 倒计时,纯 cosmetic)。
- **「进入」按钮:勾选协议后才可点**(未勾灰显)。
- 协议勾选 + 《用户协议》《隐私政策》(**占位页即可**,发朋友先放占位文案)。
- 「未注册手机号自动创建账号」提示。
- 次要:**微信登录 = 占位按钮**(可见;点了给"敬请期待"轻提示或无动作,**不接真登录**)。

## 登录行为(本版 = MOCK,别接真短信)
- **不发真短信、不接 SMS 服务商**;获取验证码只是倒计时(可加提示"测试期任意验证码可进")。
- 进入:手机号 + **任意验证码** → 直接登录。
- **账号按手机号建/取**:每个朋友各自手机号 = 各自账号、数据分开(在 Supabase create-or-fetch 该用户,**跳过 OTP**)。
  - 若 Supabase 手机账号免 OTP 创建不顺,退路 = 本地 mock 账号(单设备);但**优先手机号键**(为朋友数据分开 + 以后同步)。
- **设计成可一键换真**:以后接国内短信(阿里云/腾讯云 + 签名报备)时,只把"任意码通过"换成"校验真实 OTP",其余不动。**mock 那一处标 `//MOCK`,方便替换。**

## 红线
- mock **仅测试期**;Key/secret 不进代码(走 .env/secrets)。
- 协议占位但**链接要能打开占位页,别死链**。
- 登录成功 → 进首屏「morning. 今天打算怎么过?」。

## BE(Cursor,极少)
- 基本 FE + Supabase client 搞定;仅当手机号免 OTP 建号需要后端协助时,Cursor 出一个最小辅助,否则无活。

## 验收
1. ✅ 手机号 + 任意码 + 勾协议 → 进首屏;**不同手机号 = 不同账号/数据**。
2. ✅ 微信按钮可见、点了不报错(占位)。
3. ✅ 协议勾选门控;《用户协议》《隐私政策》链接能打开占位页。
4. ✅ mock 处有 `//MOCK` 标记,换真 SMS 只动那一处。
5. ✅ Android / iOS 一致,真机验,done 老板按效果拍。
