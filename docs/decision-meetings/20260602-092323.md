# 项目文档

目标:把『早上』这段彻底收尾交付:① 完成 routine(我的日常)功能的收尾与可验收;② 从零新增早上屏语音录入能力,让用户不止能打字、还能说话出计划。

上下文:产品为 Think & Act / 你的一日搭子(Android AI 日程搭子,像朋友不像教练,核心三段式:早 60 秒 / 白天 10 秒 / 晚 90 秒)。早上 60 秒文字闭环已跑通并验收(Task 05 morning P0 收官)。当前主线卡在 routine:后端 routines 表/RLS/plan-generate 并入(方案B)、前端『我的日常页』(方案A 挂早上屏)均尚未真正验收完,routine 暂不算交付。语音:旧交接文档写『语音已通』不算数,老板当面确认是从零做、之前没有此功能。语音明确使用已锁定的科大讯飞离线 SDK。
方案:本轮只做两件事。① Routine 收尾:补齐后端 routines 表 + RLS + CRUD,plan-generate 按方案B把当天命中(enabled=true 且 repeat_days 含今天)的 routine 当已有固定项喂 AI、回传 source=routine,前端只渲染不本地合并;前端『我的日常页』支持加/改/停用/删固定项,入口按方案A先挂早上屏。② 语音录入(从零做):早上屏加麦克风,点麦克风→说出今天→讯飞离线 SDK 转文字并自动填进输入框→用户扫一眼确认/可改一两个字→再手动点『出计划』走现有生成流程(老板最终拍板:保留确认步骤,不直接生成)。

产出标准:① Routine:在『我的日常页』能加 / 改 / 停用 / 删固定项;第二天早上这些固定项自动出现在计划里并带 routine 标记(source=routine)。② 语音录入:早上屏点麦克风→说出今天→自动转成文字填进输入框→用户确认(可改一两个字)→点『出计划』正常生成。验收以实证为准(migration/RLS/接口自测证据、截图/demo/构建或真机验证),不接受『基本完成』或自报通过;result 卡走 HTTP 提交、review=pending,最终 pass/fail 由老板在看板 UI 裁决。

约束:1) 范围只限本轮这两件,不顺手往下做白天执行屏等队列功能。2) 语音按从零做,旧文档『语音已通』作废;语音引擎锁定科大讯飞离线 SDK,不临时换别的。3) 出计划前保留语音转文字后的人工确认步骤,不做成说完直接生成。4) 沿用已锁定决策:陶土视觉、AI 语气 v1.3『不发明任务』、DeepSeek→Kimi 生产链路、key 永不进对话/代码。5) routine 字段口径以 docs/routine-field-hints.md 为准(repeat_days 0=周日..6=周六;default_time=time+timezone 合成 ISO)。

回报节点:1) 后端交 routines 表/RLS/plan-generate 并入的 result 卡 + 自测证据 → 老板 UI 裁决。2) 前端交『我的日常页』增删改停用 + 早上屏入口 + source=routine 渲染的截图/demo/真机证据 → 老板裁决。3) 前端交语音录入(麦克风→讯飞转写→填输入框→确认→出计划)真机演示证据 → 老板裁决。4) PM 把以上结果合并成一张老板验收卡(只说业务结果、产出路径、测试证据、未决风险)交老板做本轮终验。
