# 项目文档

目标:做一款以生辰八字+出生地点为核心输入的 AI 算命日历产品：用户一次性完成三层冷启动（MBTI 输入 + 生辰八字+出生地点 + 针对性灵魂问答），AI 以确定性算法合成专属「命格」永久存档；此后每天根据命格档案 + 今日变量（节气/月相/日期）推送方向性氛围引导，并生成可分享的每日专属图。

上下文:目标用户以女性为主，喜欢精致感、有分享欲的年轻人。产品差异化来源于三层输入叠加的「专属感」——生辰八字+出生地点是中国命理核心输入法，天然有「这是只属于我的」心理认同，无法被单一人格测试复制；同一个人的生辰八字+出生地点唯一且固定，不存在两次填写不一致的问题。视觉方向锁定东方仙侠/星空符文质感（精美插画 + 星图背景 + 古印符文图腾），命格名称保留动漫/玄幻感（格式：属性·称号，例如「雷系·破军命格」），美术风格描述用自有词，不直接对标任何具体游戏 IP。MBTI 作为后台标签，界面不露出品牌名。起步形态为微信小程序或 H5，验证后再做 APP。生辰八字+出生地点为公开性固定数据，不属于生物特征，合规门槛远低于人脸/掌纹；用户数据须满足基本个人信息保护要求（可查询/可删除/账户注销级联删除）。
方案:【冷启动三步，一次性】① MBTI 输入：用户直接填写已知类型；若不知道，提供快速测试入口（16 题左右）先测后填，两条路径均可进入下一步。② 生辰八字+出生地点：填写出生年月日 + 出生时辰（12 时辰选择器）+ 出生城市/地区，永久存档。③ 针对性灵魂问答：根据用户 MBTI 类型定制追问 5 道题，不同类型题目不同，答案永久存档，作为日后每日推送的核心依据。三层输入以确定性映射算法合成命格——固定输入必得固定输出，可验证，「AI」只是算法包装，不做概率性提炼。命格图为有限枚举的预制立绘库拼合（命格名称 + 属性标签 + 等级感 + 东方仙侠风插画），设计阶段须标注立绘库总量 N；命格永久存档不变。【每日推送】命格档案 + 今日变量（节气/月相/日期）→ 生成方向性/氛围性引导，以意象或隐喻表达今日能量倾向，不出现具体行动指令；内容须在神秘感与满足用户「想要方向指引」的心理需求之间取得平衡，避免过度留白导致内容空洞与次日不回访。每日输出一张可分享的专属日图（命格关键词 + 今日意象 + 一句话），日图使用预制模板 + 变量插字生成。【数据更正】生辰八字为固定数据，正常不更新；提供「修正档案」入口供填错的用户重新建档，触发命格重算。

产出标准:1. 冷启动流程跑通：三步建档完成后能生成命格名称和命格图，图片可下载/分享；MBTI 支持直接输入和快速测试两条路径，均可进入下一步。2. 命格图视觉达标：东方仙侠/星空符文质感，出 1-2 张定稿基准图作为验收锚点，女性用户看到有截图晒圈的欲望；MVP 阶段命格图为预制模板拼合（非实时 AI 出图），须标注预制立绘库总量 N 与撞格关系。3. 每日推送内容生成：给定已建档用户 + 今日日期，输出三条方向性意象引导 + 每日分享图；内容为氛围性引导，不得出现具体明确行动指令；出图成功率 ≥95%。4. 命格数据持久化：同一用户命格不变，每日内容随日期变；相同三层输入两次建档必得相同命格（固定输入锁定输出，可演示验证）。5. 「修正档案」入口存在，触发命格重算逻辑正确。6. 异常路径验收：生辰八字格式错误、时辰未选、出图失败、网络中断时有降级方案和用户提示。7. 命格体系定义：属性数 × 称号数 × 等级数的组合空间须满足同周新用户撞格率 <5%，设计阶段给出可验算公式（A 种属性 × B 种称号 × C 级等级 = A×B×C 种命格，代入预期周新用户量验证 <5%）。8. 内容安全：禁用词清单及娱乐化免责文案模板作为 CP3 交付物，内容过该清单审核才算达标。9. 数据删除：账户注销时命格档案、灵魂问答答案、每日记录级联删除，验收须演示注销后数据不可查。10. 留存与成本（CP4 go/no-go 门槛）：冷启动完成率 ≥60%；真实行为分享率（点击分享/保存按钮）≥30%；次日留存（D1）≥30%；7 日留存（D7）≥15%；每日推送打开率 ≥20%；单用户冷启动+30 日 AI/出图调用成本须在 CP1 估算范围内。

约束:- 界面不出现「MBTI」字样，只呈现命格体系自己的语言；- 生辰八字+出生地点建档后即锁定，命格一经生成不自动变更（用户主动触发「修正档案」除外）；- 视觉必须女性友好（东方仙侠/星空符文路线），不做硬核暗黑男性向；美术风格用自有词，不直接对标任何具体游戏 IP；- MVP 阶段不做 APP；命格图和每日分享图均使用预制模板 + 变量插字，不做实时 AI 出图（实时出图列为 v2）；- 每日变量来源限定为节气/月相/日期等公开数据，不引入需用户每日填写的变量；- 每日推送内容必须是方向性/氛围性/意象化引导，不得出现具体明确行动指令；饮食/健康类措辞加娱乐化免责处理，不做医疗级建议；- 命格合成算法须满足固定输入锁定固定输出（可验证）；不同 MBTI 类型的 5 道问答须差异化设计，合成权重有可验证的映射规则；- MVP 阶段每日内容生成优先用规则引擎，如用 LLM 须加内容安全边界与审核规则，并过禁用词清单；- 用户数据须满足基本个人信息保护：可查询、可删除、账户注销触发级联删除；- 命格预制立绘库数量须在设计阶段给出总量 N，撞格率须满足 <5%（以同周新用户量为计算基准）；- CP0 验证前不进全流程开发；CP4 任一 go/no-go 门槛未达不上线。

回报节点:CP0（开发前，硬性前置，目标第 1-2 周）：用可点击原型对真实目标女性用户（≥10 人）测真实分享行为（观察是否实际点击分享/保存按钮），目标真实行为分享率 ≥30%；同步完成命格体系组合空间设计，给出可验算的撞格率公式，验证同周新用户撞格率 <5%。CP0 未通过不进 CP1。CP1（目标第 3-5 周，依赖 CP0 通过）：冷启动原型可演示（三步建档 → 命格图生成），MBTI 双路径跑通，生辰八字+出生地点输入界面完成；1-2 张视觉基准图评审对齐东方仙侠/星空符文风格后再开发；每日分享图生成方案（预制模板）确认；每日内容生成方式（规则引擎 vs LLM）拍板；单用户冷启动+30 日 AI/出图调用成本估算给出。CP2（目标第 6-7 周）：命格图设计稿评审（老板看图，确认女性用户愿意截图晒圈）；验证相同三层输入两次建档命格一致（固定输入锁定输出）；预制立绘库总量 N 确认，撞格率公式复核。CP3（目标第 8-10 周）：每日内容生成逻辑跑通，给定命格档案 + 日期 → 输出三条方向性意象引导 + 分享图，确认无具体行动指令，出图成功率 ≥95%；禁用词清单及娱乐化免责文案模板交付并过审；每日推送通知机制跑通（推送到达率可测量）。CP4（目标第 12 周+）：小程序/H5 MVP 上线内测，邀请真实女性用户（≥20 人）跑完冷启动全流程，收集行为数据；go/no-go 门槛：冷启动完成率 ≥60%、真实行为分享率 ≥30%、D1 留存 ≥30%、D7 留存 ≥15%、每日推送打开率 ≥20%；任一项未达门槛回炉调整不上线；同时复核单用户 30 日成本是否在 CP1 估算范围内。
