## 0. 目标（按效果验 + 两个数）

- 点了**就出字**;录音过程**绝不被 UI 事件打断**。
- 两个验收数字:**按下 → 首字**(TTFW)、**松手 → 最终**(收尾延迟)。
- 目标参考(真机):TTFW 体感 < ~800ms、收尾 < ~1s;打到"和微信/输入法差不多"为准。

## 1. 防断（结构性,这是"保证不复发"的关键)

**根因**:录音会话被绑在 UI 的生命周期/焦点上。按住说话时,任何 UI 事件——失焦、Compose 重组、"在听…"状态条出现导致布局位移把按钮挪出手指、键盘弹出、轻微滚动——都会让手势被判成取消/松手,或让持有 WS+采音的协程随某个 Composable 一起被销毁 → 连接被拆 → 表现为"点完自动断开"。"把状态行挪到按钮下"只堵了一个触发点,触发点有一堆,必然复发。

**对策(逐条做齐):**

1. **录音会话搬出 UI 树**:WS 连接 + 音频采集 + ASR 会话由一个**稳定持有者**(ViewModel / 独立会话管理器,scope = viewModel/app,**不是** Composable)拥有。Composable 只**观察状态 + 发"开始/结束"事件**,不持有连接。**重组、离开组合都不得销毁会话**(除非显式停止)。
2. **手势不依赖焦点**:按住说话是 pointer/touch 手势,彻底删除任何"获焦才录 / 失焦即停"的逻辑。失焦从此影响不了录音。
3. **按钮命中区稳定、不位移**:录音开始时按钮不改大小/位置;"在听…"状态用**预留固定高度或浮层**呈现,绝不把按钮推走(布局一跳→指针离开按钮→touch cancel)。
4. **只在显式手势转移状态**:松手 = 结束、上滑 = 取消(像微信,容错,手指轻微移动不算取消)。失焦 / 重组 / 滚动 **都不是**结束事件。
5. **明确状态机**:`idle → connecting → listening → finalizing → done/error`,只有**真实事件**(手势 / 音频 / 服务端)能转移状态。"整理中(finalizing)"期间 UI 不能显示成"断了"。

## 2. 提速（启动延迟）

1. **凭证预取 + 缓存**(BE+FE):进页面 / 麦克风按钮一出现,就提前拿好预签名 URL;**有效期内复用**,别每次现拿。签发它的后端**保活、不冷启动**。
2. **按下即开 WS + 本地先缓冲**(FE):按住那一刻立即建 WS,**同时立刻开始采音并写本地缓冲**;WS 一就绪就把缓冲补流上去——握手那段时间被藏掉,**第一句不丢**。
   - (进阶:若腾讯容忍空闲连接,进页面就预建 WS + keepalive,体感最接近"点了就出字";空闲计费/超时让工程先确认再定。)
3. **partial 立即上屏**(FE):识别到就显示,不等整句。
4. **端上 VAD 收尾**(FE):用户一停,端上 VAD 立刻触发定稿,不傻等云端静音超时。
5. **keepalive**(FE/BE):防服务端把短暂空闲连接掐掉(也呼应"像连不上"的体感)。
6. **撤掉实时 LLM 清洗**(FE 编排):转写文本反正下游喂 DeepSeek 规划器会再清,实时再清一遍是**双重浪费 + 拖慢收尾**。只保留**热词偏置**(把用户的任务词 / Memory / 常用项喂进去提准)。

## 4. 验收

**A. 提速(两个数,真机)**
- **按下 → 首字** TTFW、**松手 → 最终** 收尾延迟,各跑几次取中位数,打到 §0 目标。

**B. 防断压力测试(关键——这条过了才算"保证不复发")**
录音过程中**刻意制造干扰**,要求**录音都不断、不丢**:
- 录音中触发一次状态变化导致 Compose 重组;
- "在听…" banner 出现 / 消失(布局变化);
- 轻微滚动 / 邻近控件布局抖动;
- 短暂切走再切回焦点。
Code 附**录屏**证明上述每一种都打不断会话。

**C. 通用**
- Android + iOS 两端录屏;**done 由老板按效果拍**,自测不算。

## 5. 防复发护栏(写进规范)

- 铁律:**录音/连接会话不得绑定 Composable 生命周期或焦点**——以后任何新页面、新人接手都守这条。
- §4-B 的防断压力测试**纳入本功能回归清单**,改动后必跑,杜绝悄悄复发。
