# Cursor 为 Owner(3 条)

**R8-01 生成不得把任务排进过去**(#1)|Owner:Cursor|无需配合
凌晨输入被排到当天 00:15(已过去),确认后直接「超过19小时」。
规则:plan-generate 的落位锚点 = **max(now, 用户明说的时间)**;用户没明说时间的任务,只能排在 now 之后。深夜(如 00:15 在规划)语境:"今天"= 从现在到睡前,不是从零点开始。用户**明说**了一个已过去的时间 → 不硬排,提案里如实问一句(放到现在开始?)。评测集补凌晨用例 2 条。
**边界:只动 plan-generate 的落位逻辑,不碰任何前端。**

**R8-02 生成期 kind 标注 + block 绝不静默重叠**(#4)|Owner:Cursor|Code 后续接 C8-03
「09:30–11:00 深度工作」和「09:30 取消会议」并存且无处理。
规则:生成时每个事项必须明确标 `kind`——「取消会议」这类即时小事 = point(与块共存是设计,不算冲突);判为 block 则引擎按 v2 冲突规则顺延,**绝不允许两个 block 静默重叠**;无重叠断言在 plan-generate 输出上也要跑。
**交接物:确认 `kind` 字段在 plan-generate 响应中逐项必含,发一条消息知会 Code(含示例响应)→ Code 才开工 C8-03。边界:Cursor 不碰渲染。**

**R8-03 跨午夜任务归属规则**(#6 数据面)|Owner:Cursor|Code 后续接 C8-08
「23:10–00:10 健身」无任何次日标识。
规则:任务**归属开始日**;真实时长照存(可跨零点);复盘/历史按开始日计;生成时尽量不主动排跨零点任务(用户明说除外)。
**交接物:确认存储口径后知会 Code → Code 做 C8-08 展示。边界:Cursor 不碰展示。**

# Code 为 Owner(8 条)

**C8-01 提醒队列严格按时间顺序**(#8)|Owner:Code|无需配合
点完顶部提醒卡「完成」,直接跳到 09:30 取消会议,跳过了 09:00 站会、09:30 深度工作。
期望:提醒按 planned_time 升序逐个来,完成/跳过一个,下一个该是谁就是谁。

**C8-02 三态判定统一一个函数**(#9)|Owner:Code|无需配合
完整计划里多个过去任务都挂「进行中」(F-16 的镜像,说明状态判定不止一套)。
期望:全 App 共用一个纯时钟制状态函数:`now < start` 未开始 / `start ≤ now < end` 进行中 / `now ≥ end 且未完成` 超时;任何页面不得自己另算。**交付物含:函数名 + 全部调用点清单。**

**C8-03 生成页与完整计划页对 point 的渲染统一**(#10,#4 展示面)|Owner:Code|**等 R8-02 交接后开工**
提案页把「取消会议」显示为独立任务,完整计划页折成钉子,不一致。
期望:提案页也按钉子规则渲染 point,两页同一套渲染逻辑。**边界:只动渲染,不碰 plan-generate 输出。**

**C8-04 横幅与主按钮的「完成」防混淆**(#7)|Owner:Code|无需配合
横幅按钮缩小并带名:「完成·起床」/「待会儿」;主任务按钮不变;横幅按钮用次级样式拉开层级。

**C8-05 「加一项」弹窗三连**(#11/#12/#13)|Owner:Code|无需配合
- #11 弹窗命中区被语音条挡 → 修层级,弹窗置于语音条之上;
- #12 空标题「加进今天」看着可点 → enabled 跟随标题非空;**顺手全局排查"视觉禁用但可点"按钮**(第三次撞同一病根);
- #13 长标题+调时长时弹窗静默消失、任务丢失 → **静默丢数据,红线**;失败必须留在弹窗内报真实错误,绝不无声关闭。

**C8-06 时间步进器到边界禁用**(#2/#3)|Owner:Code|无需配合
到 00:00 / 23:59 时对应方向按钮置灰禁用;接近边界按剩余量步进或直接禁用,别"点了没动静"。

**C8-07 建议卡布局被挤竖排**(#5)|Owner:Code|无需配合
修自适应宽度/最小宽度,长文案换行不挤压按钮。

**C8-08 跨午夜显示「次日」**(#6 展示面)|Owner:Code|**等 R8-03 交接后开工**
formatTimeRange 统一处理:end 钟点小于 start 时加「次日」前缀(`23:10–次日00:10`),全部页面生效。**边界:只动展示。**
