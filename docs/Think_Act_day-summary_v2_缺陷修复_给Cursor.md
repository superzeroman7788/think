# Think & Act ｜day-summary v2 缺陷修复(给 Cursor)

## 现象(真机,见截图)
① 今天 **5 件**:健身 ✓ / 写文档 ✓ / 休息一下(未做) / 逛街(跳过) / 陪客户吃饭 ✓ → **3 完成 / 5**
② 返回:
- praise:「今天 **2 件**里做成了 **1 件**,健身守住了,挺稳。」 → **数字错**(应是 5 件做成 3 件)
- advice:「**深度活儿**这两天好像都被往后挪了,明天要不要一早先留一块给它?」 → **今天根本没有"深度活儿"任务,凭空编**

## 根因
1. **数字错** = day-summary 在一份"错的/旧的"任务集上算,**跟 ① 审核列表不同源 / 不同时刻**(它只看到 2 件)。疑似用了早先缓存的旧汇总,没按当前任务集重算。
2. **advice 不相关** = 它**没有真实可依据的数据,在编**(或把 spec 里的例句当模板抄)。本质:好建议要"跨日模式"数据,而**模式层还没建**,所以它只能瞎说。

---

## 修复（**BE 已上线 2026-06-07**）

### 1. 数对(P0)
- day-summary 必须读**与 ① 审核列表同一份当前任务集**(同源、同时刻;**别用早些时候缓存的旧汇总**)。
- count = 当前真实 **已接受任务** 完成数 / 总数（**排除 `status=suggested` 软建议**；见 [`BE_tasks_软建议_status_suggested_契约.md`](./BE_tasks_软建议_status_suggested_契约.md)）。
- 验:用这张图(5 件含 1 软建议、3 完成)——必须输出 **「4 件做成 3 件」**,**绝不能再出现 2/1 或 5/3**。

### 2. praise 具体 + 暖(别笼统)
- 点名**真做成的**(健身、写文档、陪客户吃饭),具体、短、暖;别只说"挺稳"。

### 3. advice 只扎根真实今日数据,否则不出
- advice **只能引用今天真实存在的任务 / 状态**(真实的 未做 / 跳过 / 完成 项)。
- **绝不编今天没有的任务或规律**——没有"深度活儿"就不准提;没有跨日依据就不准说"这两天…"。
- 若没有诚实又有用的建议 → **不返回 advice**(FE 已支持:缺 advice 自动隐下块)。**宁缺毋滥。**
- 真正的跨日 / 模式建议 = 等"模式层 / 自律引擎"(单独深设计线),现在不做。

### 4. prompt 卫生
- spec 里的例句("深度活儿…""三件做成两件")只示范**口吻**,**不是模板**:禁止照抄示例的数字 / 词;**强制从 `{tasks, statuses}` 输入计算**。
- 三层保障的后处理别误伤"扎根今日"的正常句子。

## 验收
1. ✅ 这张图的数据 → **数字对(3/5)**;praise 点名真做成的;advice 要么扎根真实任务、要么不出现。
2. ✅ 再跑几个 case 验:
   - 全完成 / 0 完成 / 多跳过 → 数字都对;
   - advice **从不引用不存在的任务**;
   - 0 完成时 praise **不空吹**(见之前"差日子"要求:真而暖,不对着 0 件硬夸)。
3. ✅ 证据:几个 case 的输入(任务集)+ 输出对照贴出来。
