# 二、功能 Bug · 现在修(Code 为主)

**F-11 morning 输入非空仍「生成今天」disabled、点了没反应**(#7)
按钮可用性判断有 bug(疑似只认某一种输入来源)。期望:框内有内容即可生成。

**F-12 再次编辑时原中文内容被替换成 " urgent"**(#8)
输入状态被污染/覆盖,正常追加与光标行为坏了。期望:二次编辑是正常 append/光标插入,绝不无故替换。**注意 #16 提到旋转后"又出现旧默认输入",可能同一个状态源头,一起查。**

**F-13 提醒弹窗点「去设置」没打开系统设置,直接进了执行页**(#12)
N-04 引导链路的尾巴:点「去设置」必须真跳系统通知设置页(App 专属设置 intent)。

**F-14 收件箱删除失败:文案错配 + 整个列表被错误态替换**(#15)
"没存上,再试一次。"和删除动作不匹配;更重要的是**列表被错误态顶掉**。期望:删除失败 → 列表保持原样,条目级提示"没删掉,再试一次?";文案按动作区分。

**F-15 旋转直接锁竖屏**(#16,顺带终结 BUG-11)
旋转跳回 morning、上下文丢失、旧输入还魂——v0.1 没有横屏场景,**manifest 锁 portrait 一行解决这一类问题**。rememberSaveable 那套发正式版前再说。

**F-16 未来任务(22:00)曾显示成「进行中」**(一致性问题第 2 条)
三态判定该是纯时钟制:`now < planned_time` 必须是未开始。查执行屏/完整计划页共用的状态判定,别有第二套逻辑。

**F-17 加一项时间回拨绕到 22:00 无日期提示**(#11)
单日聚焦,不该绕回昨天:时间选择**夹在今天 00:00–23:59 内**,到 00:00 就停,不回绕。

# 三、AI 质量(Cursor)

**C-11 极短模糊输入生成垃圾计划**(#9)
输入 `urgent` 直接生成"处理紧急事项 / 用户未提供具体内容,请自行补充"——**把提示词的元话术吐给用户了**,破语气红线。
期望:输入过短/无实义 → 不生成计划,回一句搭子式追问(如"今天大概要忙点什么?随便说两句就行");prompt 里加输出质检,元话术(请自行补充/用户未提供)绝不出现在用户面前。
