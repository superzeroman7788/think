## 给 Code

**B6-01 启动页按状态路由:今天 Morning 已完成就别再进 Morning**
现状:启动一律进 Morning。
期望:启动判断——**今天已确认过计划 → 直接进「今天/执行页」**;没确认过 → Morning。

**B6-02 Morning 输入框加大、中间区块下移**
现状:计划内容稍多输入框就放不下,影响输入感。
期望:输入框显著加大(多行、随内容长高,给到屏幕约 1/3 起步),整个中间区块下移留出空间;长文本滚动顺畅。

**B6-03 Morning 与已有计划冲突:加硬判断**(与 B6-01 同根)
现状:已生成计划后再进 Morning 录入,会和现有计划冲突(也正是之前 BUG-02"重确认抹进度"、N-05"同名并存"的根源场景)。
期望:**硬门**——今天已有确认计划时:
- 不再展示 Morning 生成流;
- 若用户主动进入,提示:「你今天已经有计划了,要直接去改今天吗?」→ 按钮跳**今天页/改今天**(plan-revise 前后对比那套);
- Morning 的"生成"入口当日锁定。
> 这条落地后,BUG-02 的强提醒弹窗方案**自然废弃**(根本不会再二次确认),N-05 同名并存的入口也基本堵死。

**B6-04 删除要彻底:别只变灰,加删除按键**(真机再次复现:语音「删除学英语」后仍灰显且可点)
现状:删除后条目只是变灰留在列表里,且仍可点击。
期望:删除 = 从列表**消失**(数据层软删即可,UI 不留灰条),**所有路径一致**(点选删除、语音删除同一套);条目操作里给明确「删除」按键。
另:**skipped(跳过)任务**保留灰显,但点击只给「恢复 / 删除」两个动作,不进普通编辑,别造成"还活着"的错觉。

**B6-05 删除后同名事务加不回去**(配合 Cursor)
现状:删掉"健身"再添加"健身"会失败。
判断:大概率是软删行残留 + 唯一性/去重逻辑误伤(N-05 的去重别把"用户主动重加"也挡了)。
期望:**软删行不得阻挡同名新增**;去重只针对"重确认时机器重插",不针对用户主动添加。Code 查客户端落库,**Cursor 同步查约束/RPC**。

**B6-06 还没到时间就点「完成」,加个轻确认**
现状:未开始的任务一点就完成,太松。
期望:`now < planned_time` 时点完成 → 轻确认:「还没到时间,现在就算完成吗?」确认即完成(只拦"提前完成"这一种,正常到点完成不加摩擦)。

**B6-07 复盘白天锁定:只能看,不能改**
现状:白天就能进复盘改完成情况,破坏"今天还在进行"的感觉。
期望:复盘在**今天收尾前只读**(可看不可改),解锁条件二选一(满足其一即解锁):
- 当天所有任务都已处理(完成/跳过);**或**
- 最后一项任务的结束时间已过。
> 解锁条件务必这么写——不然"有任务没做完的一天"会永远锁着,晚上反而没法复盘了。锁定态给一句温和说明:「今天还在路上,晚点再来收尾。」

## 给 Cursor

**B6-05(配合)** 排查软删行/唯一约束/去重 RPC:确保软删后的同名标题可正常新增;重确认去重逻辑不误伤用户主动添加。

**B6-08 意图区分:删除 ≠ 跳过**(真机实证:「删除学英语」被执行成跳过)
plan-revise 意图 schema 拆开两个 op:
- `skip`(「不做了」「跳过」「今天不弄了」)→ 状态 skipped,留在列表灰显,复盘按跳过计;
- `delete`(「删除」「删掉」「去掉这项」)→ 软删,**从今天一切视图消失**(计划页/执行队列/复盘/计数均不出现)。
评测集补 4 条用例(两口径各 2,含「把学英语删了」vs「学英语不做了」)。

## 验收要点(真机)
- [ ] 已确认计划的当天:重开 App 直进今天页;主动进 Morning 被引导去「改今天」;生成入口当日锁
- [ ] Morning 输入长文本(10+ 行)输入顺畅、看得全
- [ ] 删除即消失(点选与**语音「删除X」**同一表现);删后同名可再加
- [ ] 「X不做了」= 跳过灰显,点开只有「恢复 / 删除」;「删除X」= 各视图彻底消失
- [ ] 未开始任务点完成有轻确认;到点完成无额外摩擦
- [ ] 白天复盘只读 + 温和提示;最后一项结束时间过后可改;全部处理完也可改
