# BE 改进 · plan-generate 去重（给 Cursor）

> 来源:Code（前端）。线上实测发现的体验问题,根因在生成阶段,执行屏只如实显示。

## 现象
语音口述「今天的安排」时,用户常**重复说同一件事**(口吃 / 没听清重说一遍),ASR 转写里就出现重复。`plan-generate` 当前会把这些重复**各生成一条任务**,导致当天计划里出现**多条同名、时间相近/相同**的任务。

执行屏后果:完成第一条「做文档」→ 自动前进到第二条同名「做文档」→ 用户以为"点完成没生效"。
（实测:06-06 一个计划里出现两条「做文档」09:00 + 10:40;完成是按 id 正确前进的,只是下一条也叫做文档,看着没变。执行屏逻辑无 bug。）

## 需求:在 LLM 生成阶段去重
`plan-generate`(及同理 `routine-parse` / `plan-revise` 若适用)在产出任务前**合并明显重复项**:

1. **判重口径**:标题相同或高度近似(语义同一件事)**且**时间窗相同或重叠 → 视为同一件,**合并为一条**(取更合理的时间/时长)。
2. **保留真实多段**:标题相同但**时间明显不同、是有意分块**的(如「上午做文档」「下午做文档」)→ **不要删**,但**用不同标题区分**(如 `做文档` / `做文档(续)`),避免执行屏同名困惑。
3. **只去口述重复,别误删**:不同的事(不同标题/不同意图)一律保留;宁可少合,不可错删用户真实安排。
4. 实现位置:plan-generate 的 prompt 规则 + 后处理(LLM 输出后再做一次同窗同名合并兜底)。

## 验收(附证据)
- 同一句里重复说「做文档…做文档」→ 计划只出 1 条做文档。
- 「上午做文档,下午做文档」→ 2 条,标题区分(做文档 / 做文档(续)),时间不同。
- 不同任务(做文档 / 开会 / 跑步)一条不少。
- 贴 plan-generate 前后对比日志。

## 前端侧
执行屏「完成→前进」按 id 正确(已实测),**无需改**;去重后体验自然恢复。
