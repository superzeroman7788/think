# 非今天事项 · 统一进收件箱 · 小规格(给 Cursor + Code)

> 一条规则缝死所有口子:**任何入口听到"非今天"的事,一律抽出来放进收件箱,今天的计划不动,信息一个不丢。**
> 依赖:随手记(收件箱)管道,正在建,本规格直接挂在它上面。
> 老规矩:收到回"收到 + 排期";先对账 op 定义再动工。

---

## 给 Cursor

1. **意图 schema 加一个 op**(plan-generate 与 plan-revise 共用):
```
{ op: defer_to_inbox, title, due_date, due_part? }
```
2. **判定规则**:用户话语中的事项,若其日期**不是今天**(以 `client_local_date` 为锚解析"明天/周四/下周一/X号"),生成 `defer_to_inbox`,**绝不**塞进今天、**绝不**丢弃。同一句话里"今天的事 + 明天的事"混说 → 今天的正常进计划,明天的出 defer op(评测集补这种混合用例 ≥4 条)。
3. **执行**:defer op 落库 = 调随手记的 `inbox-capture` 同一套(status=pending, due_date),与"记一笔"进来的条目无差别;到日子那天早上照常浮现。
4. **返回**:提案/重排响应里带 `deferred: [{title, due_date}]` 数组,供前端展示确认。
5. 重排引擎不受影响(defer 的事项根本不进今天的任务集)。

## 给 Code

1. **提案/前后对比界面**:响应里有 `deferred` 时,在确认区显示一行轻提示 chip(每条一行):
   `「交报告」是明天的,先放进收件箱了,到时早上提你。`
   语气照搭子(陈述,不感叹);不需要用户额外操作,确认计划时一并生效。
2. 收件箱角标/列表照常刷新(管道同随手记,无新逻辑)。
3. 入口覆盖:Morning 输入、改今天语音/打字——都走同一响应字段,**别单独写两套**。
