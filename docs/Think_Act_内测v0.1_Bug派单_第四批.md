# ✅ 现在修(给 Code)

## A · 提醒链路(这轮就是要测推送,链路断了等于白测)

**N-01 手机重启后所有 ★ 提醒静默丢失**
AlarmManager 闹钟重启即被系统清空,Manifest 无 `RECEIVE_BOOT_COMPLETED` + 开机接收器,无重排逻辑。
期望:加 BOOT_COMPLETED receiver,开机后从本地缓存任务**重排当天剩余 ★ 提醒**。

**N-02 早上确认计划后不排提醒(不进执行屏就永远不响)**
`syncReminders` 只挂在 Execution/FullPlan 的 load;`MorningViewModel.doConfirm` 落库后不排。"早上确认→锁屏出门"这个**最典型路径**一个提醒都不响。
期望:confirm 成功后同步调 `reminderScheduler.sync(...)`。

**N-03 点提醒通知没反应**
`ReminderReceiver` 没设 `contentIntent`,点了只消通知不进 App。
期望:点通知 deep link 到执行屏(当前任务)。

**N-04 通知权限只在"首次进执行屏"请求一次,拒了就全静默失败**
只用早上屏+完整计划的用户根本不会被请求权限(与 N-02 叠加 = 链路全断);拒绝过的用户之后 notify() 全部静默失败、无补救。
期望:**确认计划(要排 ★ 提醒)前**检查并请求权限;已拒绝 → 排提醒时给一次轻引导(去设置开,搭子语气,不纠缠);不要只绑在执行屏首进。

> A 组验收(真机):早上确认含 ★ 计划 → **不进执行屏**直接锁屏 → 到点响;点通知进执行屏;**重启手机** → 当天剩余 ★ 仍响。这三条全过,提醒链路才算 ✅。

## B · 数据正确性

**N-05 重确认后"已完成 + 同名新任务"并存**(配合 Cursor)
BUG-02 修复保留了 done/skipped,但重新生成时整段口述会再次包含已做完的事 → 同名一条 done 一条 planned:执行屏让你再做一遍、历史"做成/共"分母虚增。
期望:重确认落库前按**当天已有 done/skipped 任务去重**(同名/同义不重插)。Code 先查 FE 落库路径;**Cursor 同步确认** plan-generate/确认链路里的去重是否真生效(后端有去重文档但 FE 没看到防重)。真机实测:先完成一件→重新口述含该事→确认后不重复出现。

## C · 顺手修(便宜,且涉"真实报错"红线)

**N-08 亮屏挂机跨午夜仍显示昨天**(BUG-05 残留)
换天检测只挂 ON_RESUME;执行屏常亮放桌上跨 0 点不换天。
期望:在现有 30s tide ticker 里顺带检测日期变化,变了触发换天。

**N-10 录音设备初始化失败被伪装成"没听清,再说一次?"**(报告末尾附带发现)
`VoiceInputService` 把采音异常静默吞掉。这是**真实报错红线**:设备/权限问题被说成"没听清"会误导排查和用户。
期望:采音初始化失败显真实原因(麦克风被占用/无权限等),不要套"没听清"。
