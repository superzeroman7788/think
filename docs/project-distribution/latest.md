# 项目拆解方案

目标:做一款以生辰八字+出生地点为核心输入的 AI 算命日历 H5 产品，用户一次性完成三层冷启动（MBTI+生辰八字+出生地点+灵魂问答）合成专属命格永久存档，此后每天根据命格档案+今日公开变量推送方向性氛围引导，并生成可分享的每日专属图。

上下文:目标用户以女性为主，喜欢精致感、有分享欲的年轻人。产品差异化来源于三层输入叠加的「专属感」，视觉方向锁定东方仙侠/星空符文质感。起步平台为 H5（微信内+浏览器均可）。团队由 AI Agent 三人组协作：cowork（PM/协调）、cursor（后端）、codex（前端）。MVP 阶段不做 APP，不做实时 AI 出图。命格合成算法须为确定性映射——固定输入锁定固定输出。CP0 验证前不进全流程开发，CP4 任一 go/no-go 门槛未达不上线。
拆解方案:【工作拆解 · 四大模块】

① 命格体系设计（CP0 前必须完成，交 cowork 统筹）
- 定义属性数 A × 称号数 B × 等级数 C 的组合空间，给出可验算撞格率公式：同周新用户撞格率 < 5%
- 确定 MBTI 映射权重规则（不同类型5道问答差异化设计）
- 设计命格名称体系（格式：属性·称号，东方仙侠/玄幻感）
- 预制立绘库总量 N 确认（CP2 交付）
- 由 cowork 拆解，cursor 出算法设计稿，codex 出原型界面

② 冷启动三步建档（cursor 后端 + codex 前端并行）
- cursor：建档 API（MBTI 入参 + 生辰八字/出生地点存档 + 灵魂问答存档 + 命格合成确定性算法 + 数据持久化）
- codex：H5 三步建档界面（MBTI 直接输入/快速测试双路径 + 12时辰选择器 + 出生城市选择 + 命格图展示 + 下载/分享按钮）
- codex：命格图展示页（预制立绘库拼合方案，不做实时 AI 出图）

③ 每日推送与分享图生成（cursor 后端 + codex 前端）
- cursor：每日内容生成引擎（命格档案 + 节气/月相/日期公开变量 → 三条方向性意象引导）；优先用规则引擎，如用 LLM 须加内容安全边界+禁用词清单审核
- cursor：每日推送通知机制（推送到达率可测量）
- codex：每日分享图生成展示（预制模板+变量插字，不做实时 AI 出图）

④ 数据安全与修正档案（cursor 后端）
- 账户注销级联删除（命格档案/灵魂问答/每日记录全清，可演示验证）
- 「修正档案」入口（触发命格重算逻辑）
- 禁用词清单 + 娱乐化免责文案模板（CP3 交付物）

【角色分工】
- cowork（PM）：按 CP 节点拆任务、派活、追进度、汇报老板、统筹视觉基准图评审节点
- cursor（后端）：命格合成算法、每日内容生成引擎、节气/月相数据接入、API 接口、数据持久化、级联删除、成本估算
- codex（前端）：H5 三步冷启动界面、MBTI 双路径、命格图展示、每日图生成展示、分享/保存按钮
- 老板：只在 CP 节点验收，不参与日常派活；视觉基准图评审、go/no-go 裁决由老板拍板

产出标准:1. 冷启动跑通：三步建档完成后能生成命格名称和命格图，图可下载/分享；MBTI 支持直接输入和快速测试两条路径均可进入下一步
2. 命格图视觉达标：东方仙侠/星空符文质感，出1-2张定稿基准图作为验收锚点，女性用户看到有截图晒圈欲望；MVP 为预制模板拼合，须标注预制立绘库总量 N 与撞格关系
3. 每日推送生成：给定已建档用户+今日日期，输出三条方向性意象引导+每日分享图；内容为氛围性引导，不得出现具体明确行动指令；出图成功率 ≥95%
4. 命格数据持久化：同一用户命格不变，每日内容随日期变；相同三层输入两次建档必得相同命格（固定输入锁定输出，可演示验证）
5. 「修正档案」入口存在，触发命格重算逻辑正确
6. 异常路径验收：生辰八字格式错误/时辰未选/出图失败/网络中断时有降级方案和用户提示
7. 命格体系组合空间验证：A×B×C 公式代入预期周新用户量，撞格率 <5%，给出可验算公式
8. 内容安全：禁用词清单及娱乐化免责文案模板通过审核
9. 数据删除：账户注销后命格档案/灵魂问答答案/每日记录级联删除，演示验证不可查
10. CP4 go/no-go 门槛：冷启动完成率 ≥60%、真实行为分享率 ≥30%、D1 留存 ≥30%、D7 留存 ≥15%、每日推送打开率 ≥20%；单用户冷启动+30日调用成本在 CP1 估算范围内

约束:- 界面不出现「MBTI」字样，只用命格体系自己的语言
- 生辰八字+出生地点建档后即锁定，命格一经生成不自动变更（用户主动触发「修正档案」除外）
- 视觉必须女性友好（东方仙侠/星空符文路线），不做硬核暗黑男性向；美术风格用自有词，不直接对标任何具体游戏 IP
- MVP 阶段不做 APP；命格图和每日分享图均用预制模板+变量插字，不做实时 AI 出图（实时出图列为 v2）
- 每日变量来源限定为节气/月相/日期等公开数据，不引入需用户每日填写的变量
- 每日推送内容必须是方向性/氛围性/意象化引导，不得出现具体明确行动指令；饮食/健康类措辞加娱乐化免责处理，不做医疗级建议
- 命格合成算法须满足固定输入锁定固定输出（可验证）；不同 MBTI 类型的 5 道问答须差异化设计，合成权重有可验证映射规则
- MVP 阶段每日内容生成优先用规则引擎，如用 LLM 须加内容安全边界与审核规则，并过禁用词清单
- 用户数据须满足基本个人信息保护：可查询、可删除、账户注销触发级联删除
- 命格预制立绘库数量须在设计阶段给出总量 N，撞格率须满足 <5%（以同周新用户量为计算基准）
- CP0 验证前不进全流程开发（硬性前置）；CP4 任一 go/no-go 门槛未达不上线

回报节点:CP0（第1-2周，硬性前置，老板必看）：用可点击原型对真实目标女性用户 ≥10 人测真实分享行为（观察是否实际点击分享/保存按钮），目标真实行为分享率 ≥30%；同步完成命格体系组合空间设计，给出可验算撞格率公式，验证同周新用户撞格率 <5%。CP0 未通过，cowork 不得开启 CP1。

CP1（第3-5周，依赖 CP0 通过，老板必看）：冷启动原型可演示（三步建档→命格图生成），MBTI 双路径跑通，生辰八字+出生地点输入界面完成；1-2 张视觉基准图老板评审确认东方仙侠/星空符文风格后再开发；每日分享图生成方案（预制模板）确认；每日内容生成方式（规则引擎 vs LLM）拍板；单用户冷启动+30日 AI/出图调用成本估算给出。

CP2（第6-7周，老板看图）：命格图设计稿评审（老板看图，确认女性用户愿意截图晒圈）；验证相同三层输入两次建档命格一致（固定输入锁定输出，可演示）；预制立绘库总量 N 确认，撞格率公式复核。

CP3（第8-10周，老板审内容）：每日内容生成逻辑跑通，给定命格档案+日期→输出三条方向性意象引导+分享图，确认无具体行动指令，出图成功率 ≥95%；禁用词清单及娱乐化免责文案模板交付并过审；每日推送通知机制跑通（推送到达率可测量）。

CP4（第12周+，go/no-go 裁决）：小程序/H5 MVP 上线内测，邀请真实女性用户 ≥20 人跑完冷启动全流程，收集行为数据；go/no-go 门槛全项达标才上线（冷启动完成率 ≥60%、真实行为分享率 ≥30%、D1 留存 ≥30%、D7 留存 ≥15%、每日推送打开率 ≥20%）；任一项未达门槛回炉调整；同时复核单用户 30 日成本是否在 CP1 估算范围内。
